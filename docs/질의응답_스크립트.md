# 질의응답 스크립트 (발표 후 Q&A용)

사용법: 각 질문마다 **30초 답변**을 먼저 말하고, 더 묻으면 **추가 설명**으로 이어갑니다.
**솔직하게 인정할 점**은 숨기지 말고 "현재 MVP의 한계이고 고도화 계획에 있다"로 연결하세요.

## 먼저 알아둘 원칙

- 수치(정확도 89.5~95.3% 등)는 **가상(synthetic) 데이터 기준**이라고 항상 한 번 언급합니다.
- 발주·재고는 **샘플 데이터**입니다. 실제 ERP 연동은 아직 하지 않았습니다.
- 모르는 것은 "정확한 값은 확인해서 공유드리겠습니다"라고 답합니다. 추측하지 않습니다.

## 1. 로그인·보안

### Q1. 로그인은 어떻게 구현했나요?

**30초 답변**
관리자 계정 하나로 로그인하는 구조입니다. 아이디와 비밀번호를 서버에서 확인하면, 서버 비밀키로 서명한 토큰을 발급합니다. 이 토큰은 12시간 동안 유효하고, 이후 모든 데이터 요청에 이 토큰을 붙여 보냅니다. 토큰이 없거나 위조되면 서버가 요청을 거절합니다.

**추가 설명**
- 화면에서 `POST /api/auth/login`을 호출하고, 받은 토큰은 브라우저 세션(탭을 닫으면 삭제)에 보관합니다.
- 토큰은 `사용자|만료시각`에 HMAC-SHA256 서명을 붙인 형태입니다. 외부 인증 서비스나 JWT 라이브러리는 쓰지 않았습니다.
- 로그인 화면을 제외한 모든 API가 이 검사를 통과해야 합니다. 로그인 없이 호출하면 401을 반환합니다.

### Q2. 비밀번호는 안전하게 저장되나요?

**30초 답변**
현재는 서버 환경설정 파일에 두고 직접 비교하는 방식이라, 해시 저장은 아닙니다. 파일은 서버에서 소유자만 읽을 수 있도록 권한을 제한했고, 브라우저로는 내려가지 않습니다. 사용자 계정을 늘리는 단계에서 비밀번호 해시 저장으로 바꿀 계획입니다.

**솔직하게 인정할 점**
MVP라서 단일 계정과 환경변수 방식을 썼습니다. 다중 사용자 단계에서 해시(bcrypt 등)와 사용자 테이블이 필요합니다.

### Q3. 여러 사람이 쓸 수 있나요? 권한은 나뉘나요?

**30초 답변**
지금은 관리자 계정 하나뿐이고 역할 구분은 없습니다. 고도화 1순위로 관리자, 구매담당, 조회자 세 역할을 나누고, 관리자만 기준값·데이터·사용자를 관리하는 구조를 설계해 두었습니다.

**추가 설명**
- 조회는 모두, 발주 등록과 시뮬레이션은 구매담당까지, 기준값·사용자·모델 관리는 관리자만 허용하는 안입니다.
- 구현은 사용자 테이블 또는 Supabase Auth, 서버 권한 검사, 화면 메뉴 분리로 진행합니다.

### Q4. 토큰이 탈취되면 어떻게 되나요?

**30초 답변**
HTTPS로 통신하기 때문에 전송 중 탈취는 막고 있습니다. 다만 서버가 토큰을 개별로 무효화하는 기능은 아직 없어서, 유출되면 만료(12시간)까지는 유효합니다. 고도화 때 토큰 폐기와 로그인 시도 제한을 넣겠습니다.

**솔직하게 인정할 점**
로그인 실패 횟수 제한(잠금)도 아직 없습니다.

### Q5. 외부에서 데이터를 볼 수 있나요? API 키는 안전한가요?

**30초 답변**
화면 파일은 공개지만 데이터 API는 로그인 토큰이 없으면 401로 막힙니다. Supabase, Neo4j, OpenAI 키는 서버에만 있고 브라우저로 전달되지 않습니다.

## 2. 수요예측

### Q6. 어떤 모델을 썼나요? XGBoost나 랜덤포레스트는 안 썼나요?

**30초 답변**
머신러닝 모델은 쓰지 않았습니다. 자재별 월 수요 48개월에 직선 추세를 맞추고, 월별 계절지수를 곱하는 통계적 분해 방식입니다. 자재당 데이터가 48개월뿐이라 해석이 쉬운 모델로 시작했고, 가격 같은 변수를 추가한 뒤 XGBoost, LightGBM과 비교 검증할 계획입니다.

**추가 설명**
- 식은 `예측(월) = (a + b·t) × 계절지수(월)` 입니다.
- 사용한 피처는 시간 순번과 달력 월 두 가지입니다.
- 데이터가 적고 가상이라, 지금 ML을 쓴다고 정확도가 오른다는 보장이 없어서 비교 검증을 먼저 하기로 했습니다.

### Q7. 정확도 89.5~95.3%는 어떻게 계산했나요?

**30초 답변**
2022~2024년 36개월로 모델을 맞추고 2025년 12개월을 예측해, 실제값과 비교했습니다. 정확도는 100에서 MAPE(평균 절대 백분율 오차)를 뺀 값입니다. 다만 가상 데이터 기준 수치입니다.

### Q8. 원자재 가격이나 프로젝트 데이터는 왜 안 썼나요?

**30초 답변**
데이터는 이미 Supabase에 적재되어 있지만, MVP에서는 모델을 단순하게 두기 위해 쓰지 않았습니다. 고도화 2단계에서 원자재 가격, 프로젝트 착공·규모, 전력 판매량을 외생변수로 넣어 정확도가 개선되는지 검증할 계획입니다.

### Q9. 실제 업무에 바로 쓸 수 있는 수준인가요?

**30초 답변**
구조와 화면은 갖춰졌지만, 데이터가 가상이라 수치를 업무 의사결정에 바로 쓰기는 어렵습니다. 실데이터로 전환해 같은 방식으로 재검증하는 것이 첫 단계입니다.

## 3. 재고관리

### Q10. 적정재고 기준(평균 월수요 × 1.5개월)의 근거는 무엇인가요?

**30초 답변**
MVP에서 샘플 데이터를 만들면서 정한 단순 규칙입니다. 실제 정책 기준은 아닙니다. 고도화에서는 목표 서비스수준과 리드타임 변동을 반영하는 통계적 안전재고 공식으로 바꾸고, 기준 배수는 관리자 페이지에서 조정할 수 있게 합니다.

### Q11. 권장 발주량에서 발주 중 수량을 빼는 이유는 무엇인가요?

**30초 답변**
이미 발주해서 들어오는 중인 물량을 다시 발주하면 중복되기 때문입니다. `적정 재고 + 다음 달 수요 − 현재고 − 발주 중 수량`으로 계산하고, 음수면 0으로 처리합니다.

### Q12. 예상 소진일은 정확한가요?

**30초 답변**
다음 달 예측 수요를 30일로 나눠 일평균 소진량을 구하고 현재고를 나눈 값입니다. 수요가 매일 균등하다고 가정한 단순 추정이라, 월중 변동이나 입고 일정은 반영하지 않습니다.

## 4. 시뮬레이션

### Q13. 시뮬레이션 결과를 얼마나 믿어도 되나요?

**30초 답변**
수요 변동과 납기 지연이 재고와 결품에 미치는 영향을 비교해 보는 용도입니다. 비용, 공급사별 차이, 최소주문량은 반영하지 않아서 금액이나 확률로 쓰기보다는 시나리오 간 상대 비교로 보시는 것이 맞습니다.

### Q14. 결품 21은 무슨 의미인가요?

**30초 답변**
수요 15% 증가와 납기 30일 지연이 겹칠 때 부족하게 되는 수량의 합계입니다. 자재 단위(대, km, 면)가 섞여 있어 합계는 위험의 유무를 보는 용도입니다.

## 5. AI 위험 알림

### Q15. LLM이 없는 내용을 지어내지 않나요?

**30초 답변**
LLM에는 지식그래프에서 조회한 사실만 입력하고, 입력에 없는 원인이나 관계를 만들지 말라고 지시합니다. 출력은 라벨별 한 줄로 제한했고, 호출이 실패하면 그래프 사실로 만든 문장으로 대체합니다.

**솔직하게 인정할 점**
LLM이 문장을 다듬는 과정에서 표현이 달라질 수 있어, 근거 출처 표시와 검증은 고도화 항목입니다.

### Q16. 위험도 기준(10·15·20%)은 어디서 나왔나요?

**30초 답변**
시스템 설정값으로 둔 기준이고, 코드의 설정 파일에서 바꿀 수 있습니다. 관리자 페이지가 생기면 화면에서 조정할 수 있게 하겠습니다. 외부 리스크와 자연재해는 지식그래프에 입력된 심각도를 그대로 따릅니다.

### Q17. 위험 알림의 프로젝트와 Supabase 프로젝트는 어떻게 연결했나요?

**30초 답변**
두 시스템의 프로젝트명이 달라서 처음에는 공사 유형과 완료예정일로 매칭했습니다. 이후 Supabase의 해당 프로젝트 이름과 지역, 기간을 지식그래프 기준으로 맞춰 지금은 이름이 일치합니다.

**솔직하게 인정할 점**
연결 대상은 현재 2개 프로젝트이고, 가상 데이터를 맞춰 수정한 결과입니다. 실제 운영에서는 공통 프로젝트 코드를 두는 방식이 필요합니다.

### Q18. 위험 분석은 실시간인가요? 비용은 얼마나 드나요?

**30초 답변**
실시간 수집은 아직 아니고, 화면을 열면 지식그래프를 조회해 분석합니다. 결과는 30분간 캐시하며, '새로 분석'을 누를 때만 LLM을 다시 호출합니다. 호출 비용은 위험 8건 기준으로 작은 편이지만 정확한 금액은 사용량 확인 후 말씀드리겠습니다.

## 6. 데이터·운영

### Q19. 데이터는 실제 데이터인가요?

**30초 답변**
수요, 가격, 프로젝트 데이터는 Supabase에 들어 있는 가상 데이터이고, 발주·재고는 제가 생성한 샘플입니다. 실제 데이터로 전환하는 것이 고도화 1단계입니다.

### Q20. ERP와 연동되어 있나요?

**30초 답변**
아직 연동하지 않았습니다. 현재는 Supabase 테이블을 읽고 쓰는 독립 구조이고, ERP·AMS·배송시스템 연동은 로드맵 3단계에 있습니다.

### Q21. 동시 접속은 몇 명까지 가능한가요?

**30초 답변**
서버가 vCPU 2개, 메모리 약 1GB의 소형 인스턴스라 소규모 내부 사용을 가정한 구성입니다. 사용자가 늘면 인스턴스를 키우고 캐시를 도입해야 하며, 부하 테스트는 아직 하지 않았습니다.

### Q22. 장애가 나면 어떻게 되나요? 백업은요?

**30초 답변**
앱은 서비스로 등록되어 있어 장애나 재부팅 시 자동으로 다시 시작됩니다. 별도의 모니터링과 백업 체계는 아직 없어서 고도화 1단계에 넣었습니다.

**추가 설명**
데이터는 Supabase에 있어 서버가 바뀌어도 유지됩니다. Supabase의 자동 백업 범위는 요금제에 따라 다르므로 확인이 필요합니다.

### Q23. HTTPS 인증서는 유료인가요?

**30초 답변**
무료인 Let's Encrypt 인증서입니다. 90일마다 서버가 자동으로 갱신합니다.
